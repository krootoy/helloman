# Recall — умные карточки

Полноценный локальный прототип сервиса интервального обучения: аккаунты,
персональные колоды, source-grounded генерация через совместимые LLM API,
повторение, статистика и двусторонняя печать.

## Деплой на Vercel

Приложение полностью адаптировано для деплоя на **Vercel** (фронтенд раздаётся через глобальный CDN Vercel, а бэкенд на FastAPI работает как Python Serverless Function в `api/index.py`).

### Способ 1: Деплой через GitHub (рекомендуется)

1. Загрузите проект в репозиторий GitHub.
2. В панели [Vercel Dashboard](https://vercel.com/) нажмите **Add New...** -> **Project**.
3. Выберите ваш репозиторий.
4. Vercel автоматически подхватит конфигурацию из `vercel.json` и установит:
   - **Framework Preset**: Other
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
5. В разделе **Environment Variables** добавьте:
   - `RECALL_SECRET_KEY`: случайная длинная строка (для шифрования ключей LLM в базе).
   - *(Опционально для постоянных данных)* `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` (подробнее ниже).
6. Нажмите **Deploy**.

### Способ 2: Деплой через Vercel CLI

```bash
npm install -g vercel
vercel login
vercel
```

### Важно: хранение базы данных на Vercel (Serverless)

В среде Serverless (Vercel / AWS Lambda) локальная файловая система доступна для записи только во временную директорию `/tmp`.
В приложении реализовано два режима:

1. **Быстрый старт (из коробки):**
   Если переменные Turso не заданы, приложение автоматически использует базу в `/tmp/recall.sqlite3` и копирует в неё существующие данные при старте инстанса. Это позволяет сервису работать сразу без внешних настроек. Однако при перезапуске серверлесс-контейнера временные данные сбрасываются.
2. **Полноценный продакшен (Turso / libSQL Cloud):**
   Для постоянного хранения пользователей и карточек подключите бесплатную облачную SQLite базу [Turso](https://turso.tech/):
   ```bash
   # Установите CLI Turso и создайте базу:
   turso db create recall
   turso db tokens create recall
   ```
   Добавьте две переменные в Vercel Dashboard (**Project Settings -> Environment Variables**):
   - `TURSO_DATABASE_URL` = `libsql://recall-[ваш-аккаунт].turso.io`
   - `TURSO_AUTH_TOKEN` = `[токен_из_команды_выше]`
   
   Приложение автоматически определит Turso и переключится на сохранение данных в облаке.

## Frontend

```bash
cd flashcards-studio
NODE_PATH=/vercel/sandbox/node_modules node /vercel/sandbox/node_modules/esbuild/bin/esbuild src/main.jsx --bundle --minify --sourcemap --outfile=dist/assets/app.js
python3 -m http.server 4173 -d dist
```

Откройте http://localhost:4173. Если frontend работает на другом порту, задайте
`window.RECALL_API_URL` перед сборкой или используйте FastAPI как единый сервер.

## Backend

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload
```

Для единого запуска после сборки:

```bash
uvicorn backend.main:app --reload
```

Откройте http://localhost:8000 — FastAPI отдаёт собранный frontend и API.

## Настройки и безопасность

- В приложении откройте **Подключение LLM** в боковой панели до добавления
  конспекта.
- Поддерживаются OpenAI-compatible, Anthropic, Gemini и custom JSON endpoint.
- API key передаётся на backend только при сохранении подключения и хранится
  зашифрованным в SQLite; в браузерное хранилище ключ не записывается.
- Для production обязательно задайте `RECALL_SECRET_KEY` и отдельный
  `RECALL_DB_PATH`. Для удалённого frontend задайте
  `RECALL_CORS_ORIGINS` списком origin через запятую.

Пример:

```bash
RECALL_SECRET_KEY="длинный-случайный-секрет" \
RECALL_CORS_ORIGINS="http://localhost:4173" \
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

## Реализовано в прототипе

- React-интерфейс обзора, колод и статистики;
- регистрация, вход, выход и отдельные данные для каждого аккаунта;
- PBKDF2-хеширование паролей и токен сессии в SQLite;
- загрузка TXT, PDF и вставка конспекта;
- чтение DOCX (абзацы и таблицы) через backend;
- окно предпросмотра полного текста перед генерацией с реальным прогрессом;
- экран учебной сессии с ответом до открытия карточки;
- оценки «Вспомнил» и «Не вспомнил»;
- очередь повторения в интерфейсе;
- настройки endpoint / model / API key в боковой панели;
- перед сохранением настроек выполняется тестовый запрос к модели;
- выбор формата провайдера: OpenAI-compatible, Anthropic, Gemini или custom JSON endpoint;
- строгий JSON-промпт с обязательной цитатой из исходного текста;
- проверка цитаты, удаление дублей и сохранение сгенерированных карточек в SQLite;
- светлая зелёная тема и тёмная тема с переключателем;
- макет печати A4;
- печать лицевых и оборотных сторон;
- перестановка карточек под переворот по длинной или короткой стороне;
- флажок печати источника на обороте;
- FastAPI-контракт для импорта, генерации, отзывов и статистики;
- SQLite-история попыток.

## DOCX

Для чтения `.docx` backend должен быть установлен полностью:

```bash
pip install -r backend/requirements.txt
```

Ключевые пакеты — `python-docx` и `pypdf`. После установки перезапустите Uvicorn.
Frontend отправляет TXT, DOCX и PDF в `POST /api/import`, backend извлекает текст
и возвращает его в редактор конспекта. TXT читается в UTF-8 и Windows-1251.
PDF с текстовым слоем поддерживается; сканированные PDF без OCR пока нужно
предварительно распознать.

## Двусторонняя печать

В интерфейсе «Распечатать карточки» каждая страница A4 содержит 4 карточки.
Лицевая и оборотная страницы уже подготовлены в правильном порядке:

- **по длинной стороне** — для обычного книжного переворота;
- **по короткой стороне** — для переворота сверху вниз.

После нажатия «Печать на A4» браузер откроет системный диалог печати. Для
физического принтера выберите двустороннюю печать и тот же способ переворота.
Перед большой партией стоит проверить один лист.
